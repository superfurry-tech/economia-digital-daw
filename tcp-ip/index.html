Capa de Aplicación

Maneja los detalles de la aplicación de usuario en particular (ej. Telnet, FTP, SMTP, DNS, SNMP). Es un proceso de usuario que interactúa directamente con el usuario o software final, desentendiéndose del movimiento de los datos por la red.

Características Clave

  • Normalmente implementado como proceso de usuario.
  • No conoce detalles de enrutamiento o transporte físico.
  • Usa protocolos estándar con puertos bien conocidos (Well-known ports).

Arquitectura IP, Direccionamiento y Subredes

Conceptos esenciales de IP version 4, clases de direcciones y el proceso de encapsulación paso a paso.

IP

Protocolo Internet (IP)

Proporciona un servicio de entrega de datagramas no confiable (best effort) y sin conexión. Las decisiones se toman salto a salto (hop-by-hop).

Cabecera base: 20 bytes Versión 4
CID

Clases y Subredes

Direcciones IP de 32 bits divididas en clases (A, B, C, D, E) y uso de máscaras de subred (Subnet masks) para ocultar detalles internos de organización.

Notación: Dotted-decimal InterNIC
ENC

Encapsulación

Cada capa añade su propia cabecera (header) o trailer al descender en la pila. Segmento TCP -> Datagrama IP -> Trama Ethernet.

Ethernet MTU: 1500 bytes Demultiplexación
Mapeo Físico y Lógico

ARP (Address Resolution Protocol) y RARP

Las direcciones IP solo tienen sentido a nivel lógico para TCP/IP, mientras que las redes físicas como Ethernet emplean direcciones de hardware de 48 bits. ARP resuelve dinámicamente una dirección IP en su dirección física correspondiente mediante tramas de difusión (broadcast).

  • Caché ARP: Mantiene los mapeos recientes por un tiempo de expiración normal de 20 minutos.
  • Proxy ARP: Permite a un router responder peticiones ARP en una red por un host en otra red (actuando como proxy).
  • Gratuitous ARP: Un host busca su propia IP al arrancar para detectar direcciones duplicadas o actualizar cachés de vecinos.

Simulador Rápido: ¿Cómo opera ARP?

Paso 1: El usuario escribe ftp bsdi. Se resuelve el nombre a IP.
Paso 2: El emisor envía un ARP Request (Broadcast): "¿Quién tiene la IP X? Dígaselo a Y".
Paso 3: El destino responde con un ARP Reply (Unicast) con su dirección de hardware MAC.

ICMP, Protocolo Ping y Traceroute

Mensajes de control, errores de puerto inalcanzable, control de tiempo de vida (TTL) y herramientas de diagnóstico clásicas.

ICMP (Internet Control Message Protocol)

Adjunto indispensable de IP. Se utiliza para comunicar errores (como host o puerto inalcanzable, redirecciones de ruta) y mensajes de consulta (como marcas de tiempo y máscara de subred).

Echo Request / Reply: Base del programa Ping
Port Unreachable: Código ICMP por puerto inexistente
Time Exceeded (TTL=0): Base del programa Traceroute

Traceroute y el campo TTL

Traceroute opera enviando datagramas UDP con un campo TTL (Time to Live) que se incrementa progresivamente desde 1. Cada router intermedio decrementa el TTL hasta llegar a 0, generando un mensaje ICMP "Time Exceeded".

TTL inicial recomendado: 64 o 255
Identificación de ruta: Salto a salto (Hop-by-hop)
Ruteo con fuente: Soporta Loose y Strict Source Routing

Capa de Transporte: UDP vs TCP

Diferencias clave entre el transporte simple sin conexión y el flujo de datos fiable orientado a conexión.

UDP (User Datagram Protocol)

Datagramas

Simple, orientado a datagramas. Cada operación de escritura produce exactamente un datagrama UDP. Proporciona puertos y checksum opcional, pero sin garantías de entrega ni orden.

Cabecera fija: 8 bytes Usado en DNS, TFTP, SNMP, RIP

TCP (Transmission Control Protocol)

Flujo Fiable

Orientado a conexión, flujo continuo de bytes fiable con establecimiento de conexión (3-way handshake), retransmisión por temporizadores, control de congestión y ventanas deslizantes (Sliding windows).

Cabecera base: 20 bytes Usado en Telnet, FTP, HTTP, SMTP

Preguntas Frecuentes (FAQ)

Respuestas rápidas basadas directamente en los conceptos del documento original de Stevens.

El nivel de red (IP) proporciona un servicio no confiable de entrega salto a salto (hop-by-hop) en todo un interconectado de redes. En cambio, el nivel de transporte (TCP o UDP) proporciona servicios de extremo a extremo (end-to-end) entre los procesos de las aplicaciones.
El MTU es el límite superior de tamaño de trama que puede transmitir una red física (por ejemplo, 1500 bytes en Ethernet). Si un datagrama IP supera este tamaño, se fragmenta en piezas más pequeñas. Sin embargo, si un solo fragmento se pierde, todo el datagrama IP original debe retransmitirse, lo cual puede degradar el rendimiento.
Los servidores utilizan puertos bien conocidos (Well-known ports, entre 1 y 1023 administrados por la IANA) para que los clientes sepan dónde encontrarlos (ej. Telnet en 23, FTP en 21). Los clientes utilizan puertos efímeros de corta duración (típicamente entre 1024 y 5000 o superiores) asignados dinámicamente por el sistema operativo de forma única en su host.
El enrutamiento estático se configura manualmente mediante comandos de ruta en el arranque o redirecciones ICMP. El enrutamiento dinámico utiliza daemons que ejecutan protocolos (como RIP o OSPF) para que los routers intercambien información de conectividad y actualicen automáticamente las tablas del kernel ante cambios topológicos o fallos de enlaces.
