1. Introducción, Ventajas y Desventajas

En la Ingeniería de software se denomina aplicación web a aquellas aplicaciones que los usuarios pueden utilizar accediendo a un servidor web a través de Internet o de una intranet mediante un navegador. Se codifica en un lenguaje soportado por navegadores web y confía su ejecución al cliente ligero.

Ventajas Principales

  • No es necesaria ninguna instalación previa.
  • Ahorro de tiempo y espacio en disco duro local.
  • Bajo consumo de recursos y mayor seguridad de datos.
  • Multiplataforma y multidispositivo por naturaleza.
  • Uso intuitivo y actualizaciones centralizadas en servidor.

Desventajas Principales

  • Menos funcionalidades que aplicaciones nativas de escritorio.
  • Disponibilidad supeditada al proveedor de red o internet.
  • Diferencia clave: cliente web vs cliente nativo (backend vs app completa).
Bloque 02

2. Tecnologías Web

Haz clic en cada categoría para explorar los componentes tecnológicos fundamentales que sustentan el desarrollo y despliegue web moderno:

HTML

HyperText Markup Language. Describe y define el contenido web en un formato estructurado.

CSS

Cascading Style Sheets. Describe el aspecto y la presentación visual del contenido.

HTTP

Protocolo de transferencia de hipertexto para la transmisión de documentos hipermedia.

CGI

Common Gateway Interface. Permite al servidor web interactuar con programas externos para contenido dinámico.

JavaScript

Ejecutado en el navegador para crear aplicaciones interactivas y avanzadas.

PHP

Backend muy popular y eficiente, motor de CMS como WordPress, Joomla o Drupal.

Java & Python & C#

Lenguajes orientados a objetos y de propósito general orientados fuertemente al desarrollo web backend.

APIs Web & REST

Conjunto de definiciones y protocolos (GET, POST, PUT, DELETE) con formatos JSON/XML para comunicar sistemas sin conocer su implementación interna.

SVG, PNG & GIF

Gráficos vectoriales escalables, compresión sin pérdida con transparencias e imágenes en movimiento.

WebGL & ASP

WebGL para gráficos 3D/2D por canvas, y ASP como marco de Microsoft para creación dinámica.

Bloque 03

3. Tipos de Aplicaciones Web

Web Estática

Sencillas, HTML y CSS. Sin bases de datos dinámicas frecuentes. Requieren resubir archivos para cambios.

Web Dinámica

Uso de bases de datos y lenguajes backend (PHP, JS). Contenido actualizado por usuario y paneles CMS.

E-Commerce

Tiendas online con pasarelas de pago (PayPal, tarjeta) y sincronización con stocks y logística.

Portal Web

Página principal que da acceso a diversos apartados: foros, correo, buscadores y áreas de registro.

Animada (HTML5/SVG)

Efectos visuales animados mediante CSS/SVG (reemplazando Flash). No idóneas para SEO.

Con CMS

Gestores como WordPress, Drupal o Joomla para publicaciones constantes de noticias y blogs.

Bloque 04

4. Escalabilidad y Balance de Carga

La escalabilidad es la capacidad del software para adaptarse a las crecientes necesidades de rendimiento y número de usuarios. Se divide en dos enfoques principales:

Escalabilidad Vertical (Scale Up)

Añadir más recursos a un solo nodo particular (más memoria RAM, mejor CPU o disco duro más rápido).

Ventajas: Fácil de implementar, impacto mínimo en código.

Desventajas: Limitado por el hardware máximo, un fallo detiene la aplicación.

Escalabilidad Horizontal (Scale Out)

Añadir múltiples servidores (nodos) trabajando en clúster y repartiendo la carga mediante un balanceador.

Ventajas: Crecimiento casi infinito, alta disponibilidad.

Desventajas: Gran rediseño arquitectónico y mayor mantenimiento.

Balance de Carga: Hardware vs Software
Por Hardware: Dispositivos rápidos basados en conmutación de circuitos. No examinan paquetes HTTP, requiriendo gestionar sesiones en cookies o bases de datos externas.
Por Software: Examinan el paquete HTTP y registran la sesión del usuario para garantizar que siempre atienda la misma máquina del clúster.
Bloque 05

5. Microservicios vs Arquitectura Monolítica

Con los microservicios, las aplicaciones se dividen en elementos pequeños e independientes que funcionan en conjunto. Frente al modelo tradicional monolítico, destacan por su modularidad y escalabilidad independiente.

Ventajas Clave
  • • Modularidad y despliegue independiente.
  • • Escalabilidad horizontal por módulo específico.
  • • Versatilidad tecnológica (distintos lenguajes).
  • • Mantenimiento simple y rápido.
Desventajas Principales
  • • Alto consumo de memoria y CPU.
  • • Complejidad de gestión e integración.
  • • Dificultad en pruebas y test globales distribuidos.
  • • Coste de implantación inicial elevado.
Bloque 06

6. Arquitecturas Web y Modelos de Capas

Las arquitecturas modelan la aplicación definiendo sus grupos lógicos de funcionamiento y comunicación:

1. Capa de Presentación

Interfaz de usuario. Recoge datos, realiza validación básica de formato y presenta los resultados visuales.

2. Capa de Proceso / Negocio

Servidor web. Reside la lógica de negocio y reglas. Actúa de puente seguro entre la presentación y los datos.

3. Capa de Datos

SGBD encargado del almacenamiento, recuperación, modificación y mantenimiento seguro de la información.

Comparador Interactivo de Modelos Arquitectónicos

Redes P2P: Arquitectura descentralizada donde los nodos (peers) actúan simultáneamente como clientes y servidores de recursos. Ofrece gran escalabilidad y robustez sin depender de servidores centrales.
Bloque 07

7. Plataformas de Desarrollo Web

Una plataforma web es el entorno empleado para diseñar y ejecutar sitios web. Consta de 4 componentes básicos:

1. Sistema Operativo

Base donde opera el equipo servidor y aloja los servicios.

2. Servidor Web

Software que gestiona peticiones HTTP de equipos remotos.

3. Gestor de BD

Almacena y organiza sistemáticamente registros de datos.

4. Lenguaje Interpretado

Código, frameworks y bibliotecas de lógica de software.
